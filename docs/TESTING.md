# الاختبار والتحقق

لا تُعلَن مرحلة منتهية بلا دليل مسجَّل في `PROGRESS.md`. أي خلل حرج في الدفع أو الأمن أو سلامة البيانات يمنع الإطلاق.

## الطبقات

| الطبقة    | الأداة                                 | المكان                                                       | تحتاج قاعدة |
| --------- | -------------------------------------- | ------------------------------------------------------------ | ----------- |
| وحدة      | Vitest                                 | `packages/domain/src/*.test.ts`، `apps/web/src/**/*.test.ts` | لا          |
| تكامل     | Vitest على PostgreSQL حقيقي            | `packages/db/src/*.integration.test.ts`                      | نعم         |
| متصفح     | Playwright على البناء الإنتاجي         | `apps/web/e2e/*.spec.ts`                                     | نعم         |
| ثابت      | ESLint صارم بالأنواع، Prettier، `tsc`  | الجذر                                                        | لا          |
| اعتماديات | `pnpm audit --prod --audit-level high` | CI                                                           | لا          |

## الأوامر

```bash
export DATABASE_URL=postgresql://masar:masar@127.0.0.1:5432/masar_test SITE_URL=http://127.0.0.1:3100
pnpm lint && pnpm format:check && pnpm typecheck
pnpm test                              # وحدة
pnpm db:migrate && pnpm test:integration
SEED_DEMO_DATA=yes pnpm db:seed:demo   # بيانات الباقات التجريبية لاختبارات المتصفح
pnpm build && pnpm e2e                 # المتصفح يحتاج بناءً حديثًا
```

لتشغيل نسختين معًا على الجهاز نفسه: `PLAYWRIGHT_PORT=3200` مع `SITE_URL=http://127.0.0.1:3200` (الافتراضي 3100).

قاعدة الاختبار لأول مرة (PostgreSQL محلي):

```bash
service postgresql start
su postgres -c "psql -c \"CREATE ROLE masar LOGIN PASSWORD 'masar' CREATEDB\""
su postgres -c "psql -c \"CREATE DATABASE masar_test OWNER masar\""
```

CI (`.github/workflows/ci.yml`) يشغّل التسلسل نفسه على كل رفع وطلب دمج.

## قواعد

- اختبار لكل سلوك جديد، ولكل خلل يُصلَح اختبار يثبت عودته مستحيلة.
- المنطق المالي وآلات الحالة تُختبر في `packages/domain` بلا قاعدة ولا شبكة.
- اختبارات التكامل تنظّف بياناتها وتعمل بالتتابع (قاعدة واحدة مشتركة).
- اختبارات المتصفح على `next start` مربوطًا بـ`127.0.0.1` (ربط النشر الفعلي) — انظر القرار 8.
- لا تخطٍّ ولا تعطيل لاختبار لتنجح الفحوص.
- المنطقة الزمنية للعمل `Asia/Riyadh`؛ اختبارات التواريخ تثبّت الوقت صراحةً.

## البيع (من المرحلة 3)

- `pnpm --filter @masar/db orders:expire` يُنهي الطلبات الفائتة ويطبع عددها؛ اختبار تكامل يشغّله فعلًا.
- اختبارات التكامل للبيع تفرّغ جداول البيع في القاعدة المشتركة، ومنها كوبونات البذرة التجريبية وروابط إضافاتها: **أعد `SEED_DEMO_DATA=yes pnpm db:seed:demo` قبل `pnpm e2e`** محليًا (CI يبذر بعد التكامل).
- اختبار المخطط يشغّل `prisma migrate diff` على قاعدة ظل مؤقتة `<db>_shadow`، فدور قاعدة الاختبار يحتاج `CREATEDB`.
- Playwright يشغّل خادمين من البناء نفسه: 3100 والعلم مغلق صراحةً (`CHECKOUT_ENABLED=false`، يثبت 404 وزر واتساب)، و3101 والعلم مفتوح لمسار الشراء (`e2e/checkout.spec.ts`، مشروعا `checkout-390` و`checkout-1440`). لقطات المقاسات السبعة لصفحتي البيانات والمراجعة مرة واحدة في `checkout-1440`.
- كل اختبار شراء يرسل `X-Forwarded-For` عشوائيًا، فحدود المحاولات لكل عنوان (القرار 42) لا تتراكم بين الاختبارات. منطق الحدود نفسه مختبر وحدةً.

## الدفع (من المرحلة 4أ)

- لا شبكة في أي اختبار: محوّل Moyasar يُختبر بـ`fetch` محقون وحمولات بشكل أمثلة الوثائق (`packages/payments/src/moyasar/fixtures.ts`)، والتنسيق بمزوّد الاختبار.
- `pnpm test:integration` يشغّل تكامل `@masar/db` ثم `@masar/payments` بالتتابع على القاعدة نفسها. مساعدات الاختبار المشتركة في `@masar/db/test-support`.
- Playwright يشغّل ثلاثة خوادم بمنافذ مشتقة من `PLAYWRIGHT_PORT` (الافتراضي 3100): الأساس (الشراء مغلق)، و+1 (الشراء مفتوح بلا مزوّد)، و+2 (مزوّد الاختبار، مشروعا `payments-390` و`payments-1440`). اختبارات الدفع تقرأ أثرها من `DATABASE_URL` نفسها التي يعمل عليها الخادم.
- الطلب لا يُنهى ومحاولته حيّة، فاختبار «دفعة على طلب منتهٍ» يعطّل السدّ T9 داخل معاملة (`forceExpireOrder`، قاعدة اختبار فقط).

## المراجعة البصرية (من المرحلة 2)

لقطات Playwright حقيقية عند: 360، 390، 430، 768، 1024، 1440، 1920. تُراجع اللقطات نفسها لا الكود، بالعربية (RTL) والإنجليزية، مع محتوى مختلط اللغة والأرقام والعملة. فحص الوصول الآلي يُضاف مع أول واجهة حقيقية.

`e2e/screens.spec.ts` يلتقط المقاسات السبعة للصفحات الثلاث باللغتين في `apps/web/screens/` (خارج git)، ويفشل عند أي تمرير أفقي أو خطأ console (ومنها مخالفات CSP). CI يحفظها مرفقًا باسم `screens`.
`e2e/a11y.spec.ts` يفحص WCAG 2.2 AA آليًا (axe). الفحص الآلي لا يغني عن تجربة قارئ الشاشة يدويًا.
