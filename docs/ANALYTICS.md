# التحليلات والقياس

**الحالة:** مخطط. التنفيذ في المرحلة 5، وقياس المقالات في المرحلة 7.

**مفتاح التصنيف:** `[حقيقة]` · `[متطلب]` · `[توصية]` · `[افتراض]` · `[خارجي]` · `[لاحقًا]`.

## 1. المبادئ `[متطلب]`

1. **`purchase` يصدر من الخادم فقط**، بعد دفع متحقق منه من المزوّد. لا حدث شراء لطلب غير مدفوع، ولا من صفحة النجاح في المتصفح.
2. القيمة والعملة في الحدث من الطلب نفسه (بالهللة داخليًا، وتُحوَّل عند الإرسال).
3. الحدث يُعرَّف مرة واحدة في مكان واحد، ثم يُرسل للوجهات. لا تعريفات متفرقة في الصفحات.
4. لا وسم إعلاني قبل موافقة الزائر.
5. لا بيانات شخصية لمنصات الإعلان دون أساس نظامي وضوابط.
6. كل رقم في لوحة الإدارة له طريقة حساب موثقة ويخدم قرارًا.

## 2. تصنيف الأحداث

| الحدث                | متى                          | المصدر       | أهم الحقول                                   |
| -------------------- | ---------------------------- | ------------ | -------------------------------------------- |
| `view_item_list`     | عرض قائمة الباقات أو البرامج | متصفح        | القائمة، العناصر                             |
| `view_item`          | فتح منتج، أو ظهور توصية مقال | متصفح        | المنتج، المقال إن وُجد                       |
| `select_item`        | اختيار منتج أو ضغط توصية     | متصفح        | المنتج، الموضع (وسط/نهاية)                   |
| `add_to_cart`        | تثبيت الاختيار والإضافات     | متصفح        | العناصر، القيمة                              |
| `begin_checkout`     | إنشاء الطلب                  | خادم + متصفح | مرجع الطلب، القيمة                           |
| `add_payment_info`   | اختيار وسيلة الدفع           | متصفح        | الوسيلة                                      |
| `purchase`           | دفع متحقق                    | **خادم فقط** | مرجع الطلب، القيمة، العملة، العناصر، الكوبون |
| `refund`             | اكتمال استرداد               | خادم فقط     | مرجع الطلب، المبلغ                           |
| `generate_lead`      | طلب «احجز تقييمًا»           | خادم + متصفح | الخدمة                                       |
| `membership_renewed` | تجديد مدفوع متحقق            | خادم فقط     | مرجع الطلب، القيمة                           |

الأسماء تتبع تسمية التجارة الإلكترونية في GA4 حيث وُجدت؛ `membership_renewed` حدث خاص.

## 3. الوجهات

| الوجهة                           | من المتصفح    | من الخادم            |
| -------------------------------- | ------------- | -------------------- |
| Google Analytics 4               | نعم (بموافقة) | `purchase` و`refund` |
| Google Tag Manager               | حاوية الوسوم  | —                    |
| Google Ads                       | وسم التحويل   | تحويل الشراء المتحقق |
| Meta Pixel + Conversions API     | نعم (بموافقة) | نعم                  |
| Snapchat Pixel + Conversions API | نعم (بموافقة) | نعم                  |

`[خارجي]` يُتحقق من الوثائق الرسمية قبل التنفيذ (لم تُقرأ بعد):

- حقول واجهة Meta الخادمية وقاعدة إزالة التكرار بين المتصفح والخادم.
- حقول واجهة Snapchat الخادمية ومعرّف إزالة التكرار.
- صيغة تجزئة الجوال والبريد المطلوبة لكل منصة.
- بروتوكول القياس في GA4 للأحداث الخادمية.
- متطلبات الموافقة لكل منصة.

لا تُخترع أسماء حقول؛ كل حقل برابط وثيقته.

## 4. إزالة التكرار

- لكل حدث معرّف واحد يُولَّد مرة ويُرسل من المتصفح ومن الخادم بنفس القيمة.
- لـ`purchase`: المعرّف مشتق من مرجع الطلب، فلا يُحتسب الشراء مرتين مهما تكرر الإرسال.
- الإرسال الخادمي عبر طابور مع إعادة محاولة؛ فشل وجهة لا يعطّل الطلب.
- سجل لكل إرسال: الوجهة، الحدث، النتيجة.

## 5. الإسناد

| العنصر          | القاعدة                                                                                                                                         |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| ما يُلتقط       | `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`، ومعرّفات النقرات المدعومة (قوقل، ميتا، سناب شات)، والمُحيل، وصفحة الهبوط |
| أول لمسة        | تُحفظ عند أول زيارة ولا تُستبدل                                                                                                                 |
| آخر لمسة        | تُحدَّث عند كل وصول بحملة جديدة                                                                                                                 |
| الختم على الطلب | عند إنشاء الطلب تُنسخ اللمستان إلى `attributions` ولا تتغير بعدها                                                                               |
| المقال          | معرّف المقال والتوصية التي ضُغطت يُختمان على الطلب                                                                                              |
| التخزين         | كعكة طرف أول؛ القيمة المعتمدة ما خُتم على الطلب في القاعدة                                                                                      |

`[توصية]` تقارير الحملات تُبنى من `attributions` المربوطة بطلبات مدفوعة، لا من أرقام منصات الإعلان وحدها.

## 6. الموافقة `[متطلب]`

- شريط موافقة عند أول زيارة: ضروري (دائمًا)، تحليلات، إعلانات.
- بلا موافقة: لا وسوم إعلانية، ولا إرسال خادمي يحمل معرّفات شخصية.
- القياس الداخلي للطلبات (غير شخصي، طرف أول) يعمل دائمًا لأنه سجل تجاري.
- الموافقة تُسجَّل في `consents` بنصها وتاريخها ونسختها، ويمكن سحبها.
- نص الشريط وأساسه النظامي يُراجعان قانونيًا (انظر `SECURITY.md`).

## 7. قياس الإيراد لكل مقال

الغرض: المقال يُحاسَب بما باع، لا بما جلب من زيارات.

| المقياس          | الحساب                                            |
| ---------------- | ------------------------------------------------- |
| إيراد المقال     | مجموع الطلبات المدفوعة المختوم عليها معرّف المقال |
| نسبة ضغط التوصية | `select_item` من المقال ÷ مشاهدات المقال          |
| تحويل المقال     | طلبات مدفوعة من المقال ÷ مشاهداته                 |
| أداء الموضع      | مقارنة التوصية الوسطى بالختامية                   |
| ليدات المقال     | `generate_lead` المختوم عليها المقال              |

- قاعدة المراجعة: مقال بلا إيراد ولا ليدات بعد ستة أشهر يُدمج أو يُعاد كتابته.
- نافذة الإسناد للمقال (كم يومًا بين القراءة والشراء): غير محسوم — `[توصية]` تُحدَّد بعد شهر من البيانات.

## 8. مؤشرات اللوحة

معرّفة بطريقة حسابها في `PRODUCT_SPEC.md` (القسم 3). قواعدها:

- مصدر الإيراد والطلبات قاعدة المنصة، لا أدوات التحليل.
- قمع الدفع: `begin_checkout` ← `add_payment_info` ← `purchase` لكل وسيلة ولكل مصدر.
- تكلفة الاكتساب تحتاج إنفاق الحملات من الـCRM (`ad_daily`) `[خارجي]`.
- خط الأساس من متجر سلة وسجل `sales` قبل الإطلاق؛ لا أرقام حالية مفترضة.

## 9. الأداء والخصوصية كقيود

- سكربتات الطرف الثالث تُحمَّل بعد الموافقة وبلا حجب للعرض الأول.
- كل وسم جديد يُبرَّر بقرار يخدمه؛ ما لا يُستعمل يُزال.
- لا تسجيل جلسات ولا خرائط حرارية في النسخة الأولى `[لاحقًا]`.

## 10. غير محسوم — قرار المالك

- حسابات GA4 وGTM ومديري الإعلانات: موجودة أم تُنشأ؟
- هل يوافق المالك والمراجع القانوني على إرسال جوال مجزّأ لمنصات الإعلان بموافقة العميل؟
- نافذة الإسناد المعتمدة للحملات وللمقالات.
