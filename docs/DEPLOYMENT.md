# النشر

**الحالة:** حزمة معاينة جاهزة ومختبرة محليًا (`deploy/`)، بانتظار تشغيل `bootstrap.sh` على خادم المالك. لا نشر إنتاج.

## قواعد لا استثناء فيها

- لا نشر للإنتاج ولا نقل نطاق دون أمر صريح من المالك.
- `mmastersway.com` لا يُمس حتى يأمر المالك بالنقل.
- الأسرار في أسرار GitHub ومتغيرات بيئة الخادم فقط. لا كلمة مرور خادم في المحادثة ولا في git.
- بيئة الاختبار والإنتاج معزولتان: قاعدتان ومفاتيح دفع مختلفة.

## متغيرات البيئة

| المتغير                   | الغرض                                             | ملاحظة                                                                                                                                      |
| ------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`            | اتصال PostgreSQL                                  | سر                                                                                                                                          |
| `SITE_URL`                | الرابط العام                                      | https إلزامي في الإنتاج (يرفضه الإقلاع غير ذلك)                                                                                             |
| `SITE_INDEXABLE`          | فتح الفهرسة                                       | `true` على النطاق الرسمي فقط وبأمر المالك؛ غيابه = مغلق                                                                                     |
| `APP_VERSION`             | الإصدار الظاهر في `/api/health`                   | يضبطه النشر                                                                                                                                 |
| `CHECKOUT_ENABLED`        | فتح الشراء                                        | مغلق افتراضيًا. على رابط عام مرفوض إلا بإذن صريح `PAYMENTS_PUBLIC_SANDBOX=yes` مع Moyasar التجريبي وفهرسة مغلقة (القرار 54، بانتظار المالك) |
| `ADMIN_SECRET_KEY`        | فتح لوحة التحكم `/admin` وتشفير سر التحقق بخطوتين | سر. 32 بايتًا base64. غيابه = اللوحة مغلقة (404)؛ قيمة ناقصة أو قصيرة ترفض الإقلاع. يولَّد على الخادم فقط (قسم «لوحة التحكم»)               |

## قيود معروفة للتشغيل

- الخادم يُربط بـ`127.0.0.1` خلف خادم عكسي يتولى TLS. توجيه اللغات مصمَّم ومختبَر على هذا الربط (القرار 8).
- `/api/health` يرجع 200 والإصدار إن كانت القاعدة تجيب، و503 إن لم تجب: يُستعمل لفحص ما بعد النشر والمراقبة.
- الترحيلات تُطبَّق بـ`pnpm db:migrate` قبل تشغيل الإصدار الجديد.

## المهام المجدولة (إلزامية مع الدفع، غير مثبَّتة بعد)

**مهمة المطابقة إلزامية متى ضُبط مزوّد دفع.** الإشعار يُرد عليه 2xx ثم يُعالَج بعد الرد؛ إن أُعيد تشغيل العملية في تلك اللحظة، أو لم يصل الإشعار، أو لم يعد العميل، فالمطابقة وحدها تحسم المحاولة. بلاها تبقى المحاولة حيّة وطلبها محجوزًا، ولا يُفعَّل اشتراك دُفع ثمنه. ومعها `orders:expire` (القرار 41). كل سطر `payment.webhook_processed` في السجل يذكر نتيجة معالجة الإشعار (`synced` أو `busy` أو `skipped:…` أو `unknown_reference` أو `provider_error`).

مثال بمؤقت systemd (**غير مثبَّت**: يُنشأ على الخادم عند ربط المزوّد، والمسار واسم الخدمة بحسب الحزمة):

```ini
# /etc/systemd/system/masar-payments-reconcile.service
[Unit]
Description=Masar payments reconcile
[Service]
Type=oneshot
WorkingDirectory=/opt/masar/deploy
ExecStart=/usr/bin/docker compose exec -T app pnpm --filter @masar/payments payments:reconcile

# /etc/systemd/system/masar-payments-reconcile.timer
[Unit]
Description=Run payments reconcile every 2 minutes
[Timer]
OnBootSec=2min
OnUnitActiveSec=2min
[Install]
WantedBy=timers.target
```

ثم `systemctl enable --now masar-payments-reconcile.timer`، ومثله لـ`orders:expire` (`pnpm --filter @masar/db orders:expire`). الدورة تقفل نفسها فلا تتداخل دورتان، وتقرأ الإعداد من بيئة الحاوية نفسها. يُتحقق بعد التثبيت من `journalctl -u masar-payments-reconcile` أن السطر `Payments reconcile {…}` يظهر كل دورة.

### المكوّنات (`deploy/`)

- `Dockerfile`: صورة الموقع من جذر المستودع. البناء بلا أسرار.
- `start.sh`: ترحيلات القاعدة ثم البذرة التجريبية (إن طُلبت صراحةً) ثم الموقع.
- `compose.yml`: PostgreSQL 16 والموقع وCaddy (شهادة Let's Encrypt تلقائية). الموقع والقاعدة بلا منافذ مكشوفة؛ Caddy وحده على 80 و443.
- `bootstrap.sh`: تجهيز الخادم مرة واحدة، وتكراره آمن.
- `update.sh` و`masar-update.timer`: كل دقيقتين يجلب الفرع، ويعيد البناء فقط إن تغيّر أو توقف الموقع. قفل يمنع تشغيلين متزامنين.

### الأسرار

لا شيء منها في git ولا في المحادثة:

- **كلمة مرور القاعدة** يولّدها `bootstrap.sh` على الخادم في `deploy/.env` (صلاحية 600).
- **الوصول إلى المستودع** بمفتاح نشر للقراءة فقط يُنشأ على الخادم، ويضيف المالك جزءه **العام** في إعدادات GitHub. النشر يسحب من الخادم، فلا يحتاج GitHub أي مفتاح للخادم.

### التشغيل الأول (المالك، مرة واحدة)

1. افتح طرفية الخادم من لوحة Hostinger (Browser terminal) كمستخدم root.
2. الصق السكربت كاملًا (من صفحة المعاينة، زر النسخ)، ثم شغّله.
3. يطبع مفتاحًا عامًا: أضفه في GitHub ← المستودع ← Settings ← Deploy keys، بلا صلاحية كتابة. السكربت ينتظر ويكمل وحده.
4. في النهاية يطبع رابط الموقع.

### لوحة التحكم (المالك، مرة واحدة على الخادم)

اللوحة مغلقة حتى تُنفَّذ الخطوتان. كل الأوامر في طرفية الخادم (Browser terminal في لوحة Hostinger) كمستخدم root، ولا شيء منها يُكتب في المحادثة.

**1. ولّد المفتاح واكتبه في `deploy/.env`** (سطر واحد؛ المفتاح لا يُطبع على الشاشة، وتكرار الأمر لا يغيّر مفتاحًا موجودًا):

```bash
grep -q '^ADMIN_SECRET_KEY=' /opt/masar/deploy/.env || printf '\nADMIN_SECRET_KEY=%s\n' "$(openssl rand -base64 32)" >> /opt/masar/deploy/.env
```

ثم أعد تشغيل الموقع ليقرأه:

```bash
/opt/masar/deploy/update.sh --force
```

**2. أنشئ حساب المالك** (تفاعلي: يسأل عن البريد والاسم وكلمة المرور من لوحة المفاتيح، وكلمة المرور لا تظهر أثناء الكتابة):

```bash
docker compose -f /opt/masar/deploy/compose.yml --env-file /opt/masar/deploy/.env exec app pnpm admin:create-owner
```

ثم افتح `https://<النطاق>/admin/login`، وادخل بالبريد وكلمة المرور، وامسح رمز QR بتطبيق تحقق (Google Authenticator أو Microsoft Authenticator)، واحفظ رموز الاسترجاع العشرة خارج الجهاز. بقية الموظفين يضيفهم المالك من «الموظفون».

**عند الحاجة فقط** (بالصيغة نفسها، بتغيير آخر كلمة):

| الأمر                             | متى                                                                                     |
| --------------------------------- | --------------------------------------------------------------------------------------- |
| `pnpm admin:reset-owner-mfa`      | فقد المالك جواله ورموز الاسترجاع: تُمحى خطوته الثانية ويسجّلها من جديد عند دخوله التالي |
| `pnpm admin:reset-owner-password` | نسي المالك كلمة مروره: يكتب كلمة جديدة من لوحة مفاتيح الخادم، وتُلغى جلساته             |

**قواعد المفتاح:**

- نسخة احتياطية من `deploy/.env` خارج الخادم مع بقية الأسرار. ضياع المفتاح أو تغييره يبطل أسرار التحقق بخطوتين المخزَّنة: يدخل كل موظف برمز استرجاع أو يعيد المالك ضبطه (والمالك بـ`admin:reset-owner-mfa`). كلمات المرور لا تتأثر.
- حذف السطر وإعادة التشغيل يغلق اللوحة فورًا (404) دون مسّ البيانات.
- الأوامر الثلاثة ترفض العمل بلا طرفية حقيقية، فلا تُشغَّل من سكربت ولا تقبل كلمة مرور من وسيط أو متغير بيئة.

### الاختبار المحلي للحزمة

ملف `.env` تجريبي بجانب `compose.yml` (لا يُرفع): `DB_PASSWORD` أي قيمة، `SITE_HOST=:80`، `SITE_URL=http://localhost:8080`، `SEED_DEMO_DATA=yes`. ثم:

```bash
docker build -f deploy/Dockerfile -t masar-app:test .
```

```bash
cd deploy && docker compose -f compose.yml -f test.override.yml --env-file .env up -d --no-build
```

نتيجة الاختبار (2026-11-25): الحزمة كاملة خلف Caddy، الترحيلات والبذرة، الصفحات 200 و404 الصحيحة، `/api/health` سليم، الخطوط تُحمَّل، صفر أخطاء في المتصفح، والتعافي بعد إعادة تشغيل الموقع. قرارات `update.sh` الأربع مختبرة (أول تشغيل، لا تغيير، إيداع جديد، إجبار).

## نقل النطاق الرسمي (المرحلة 9، بأمر المالك)

1. خريطة تحويل 301 من روابط متجر سلة الحالية إلى الجديدة، مراجَعة قبل النقل.
2. تحويل DNS.
3. `SITE_INDEXABLE=true` والتحقق من غياب ترويسة `noindex`.
4. خريطة الموقع ومراقبة أخطاء الزحف.
