# المعمارية

الحالة: المراحل 1 إلى 3 منفَّذة (المرحلة 3 محرك البيع بلا دفع حي، خلف علم مغلق). ما تحت «مخطط» لم يُبنَ بعد. القرارات ومبرراتها في `DECISIONS.md`.

## الصورة العامة

```
 Snapchat / Instagram / Google / Search
                 │
        ┌────────▼──────────────────────────────────────┐
        │ apps/web — Next.js (عملية Node واحدة)          │
        │  صفحات مُخدَّمة من الخادم  │  واجهات /api      │
        │  src/server: env, db, http, logger            │
        └───┬───────────────┬───────────────────────────┘
            │               │ يستورد
   ┌────────▼─────┐  ┌──────▼──────────┐
   │ packages/db  │  │ packages/domain │  بلا إطار ولا قاعدة
   │ Prisma + PG  │  │ قواعد العمل     │
   └──────┬───────┘  └─────────────────┘
          │
   ┌──────▼─────┐   مخطط: عملية مهام للمطابقة وإعادة المحاولة،
   │ PostgreSQL │   مزوّدو الدفع، أحداث موقّعة إلى الـCRM، دفترة للفواتير
   └────────────┘
```

## الحدود (يفرضها lint لا الاتفاق)

| الطبقة                | تستورد من        | ممنوع عليها                                           |
| --------------------- | ---------------- | ----------------------------------------------------- |
| `packages/domain`     | لا شيء           | Next، React، قاعدة البيانات (`no-restricted-imports`) |
| `packages/db`         | Prisma           | منطق عمل                                              |
| `apps/web/src/server` | `domain`، `db`   | أن يُستورد من مكوّن عميل (`server-only`)              |
| `apps/web/src/app`    | `server`، `i18n` | SQL أو حساب سعر                                       |

الحزم الداخلية تُصدَّر كمصدر TypeScript ويترجمها Next (`transpilePackages`)، فلا خطوة بناء لها.

## مسار الطلب

1. قواعد `next.config.ts`: الترويسات الأمنية، تحويل `/ar/...` إلى الرابط بلا بادئة، ثم إعادة كتابة كل مسار بلا لغة إلى `/ar/...` داخليًا.
2. `src/proxy.ts`: يضيف `X-Robots-Tag: noindex` ما لم يكن `SITE_INDEXABLE=true`.
3. `app/[locale]/layout.tsx`: يضبط `lang` و`dir`. الصفحات تُولَّد ثابتة لكل لغة.
4. الواجهات (`app/api`): تُغلَّف بـ`withErrorHandling`.

## اللغات

- العربية الأساس بلا بادئة (`/memberships`)، والإنجليزية تحت `/en`.
- القاموس العربي (`i18n/dictionaries/ar.ts`) يحدد شكل المفاتيح؛ نقص مفتاح في لغة أخرى خطأ أنواع.
- `localizedPath()` المصدر الوحيد لبناء الروابط بين اللغات.

## الأخطاء

- خطأ عمل متوقع: `DomainError` (صنف + مفتاح سبب + حقل) أو `Result` بلا رمي.
- عطل غير متوقع: استثناء عادي.
- `problemFromError` يحوّل الاثنين إلى `application/problem+json` (RFC 9457): خطأ العمل يكشف مفتاح سببه، وكل ما عداه 500 عام بلا تفاصيل مع `requestId` يُسجَّل في الخادم.
- الواجهة تترجم مفتاح السبب من القاموس؛ الخادم لا يرسل نصًا حرًا.

## الإعداد

`parseEnv` يتحقق من متغيرات البيئة عند إقلاع الخادم (`src/instrumentation.ts`): إعداد خاطئ أو ناقص يمنع الإقلاع. البناء نفسه لا يحتاج أسرارًا. رسالة الرفض تذكر اسم المتغير لا قيمته. المتغيرات في `.env.example`.

## السجلات

`logger`: سطر JSON لكل حدث باسم ثابت. ممنوع تسجيل أسرار أو بيانات بطاقات أو جوال كامل.

## محرك البيع (المرحلة 3)

التصميم الكامل في `PHASE3_COMMERCE_DESIGN.md`. ثلاث طبقات، والقرار كله في المجال:

| الطبقة                                   | ما فيها                                                                                                                                                                                                                          |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/domain/src/commerce/pricing`   | التقريب (`mulDivHalfUp`، `allocateByLargestRemainder` بـBigInt)، والضريبة المضمَّنة لكل سطر، ورمز الكوبون، وأهلية العروض، والسلة، و`priceCart`. دوال خالصة بالهللة                                                               |
| `packages/domain/src/commerce/lifecycle` | آلات حالة الطلب والاشتراك والاسترداد (جداول، والمحجوب منها `policy.undecided.*`)، و`decideSettlement`، والتواريخ (`addMonthsClamped`)، وبدء الاشتراك، والمشتري، وبصمة الطلب                                                      |
| `packages/domain/src/commerce/checkout`  | `checkoutBlockers`، و`buildOrderDraft` و`buildQuote` (الدالتان الحاكمتان: من الحقائق إلى لقطة الطلب أو العرض)، وطلب التقييم                                                                                                      |
| `packages/db/src/commerce`               | يجمع الحقائق تحت الأقفال ويستدعي المجال ويكتب ناتجه: `quoteCart`، `createOrder`، `markOrderPaid`، `expireDueOrders`/`expireAllDueOrders`، `findOrderByPublicToken`، `createAssessmentRequest`، `listPlanAddons`. لا قرار عمل هنا |
| `apps/web/src/server/checkout`           | العلم (`requireCheckout`)، والعرض العام، والإجراء `submitCheckout`، وحدود المحاولات (`throttle.ts`)، وطيّ أسباب الكوبون العامة (`public-errors.ts`)، والتسجيل المنقّح                                                            |
| `apps/web/src/components/checkout`       | نماذج عرض تُحسب على الخادم (`quote-view`، `review-view`)، والمكوّن العميل الوحيد `DetailsForm` (`useActionState`)                                                                                                                |

**ترتيب الأقفال الثابت** (أي ترتيب آخر يفتح باب التعانق):

- `createOrder`: قفل استشاري على مفتاح عدم التكرار ← `customers` FOR UPDATE ← `product_versions` FOR SHARE بترتيب المعرّف ← `promotions` FOR UPDATE بترتيب المعرّف ← الطلبات الفائتة FOR UPDATE SKIP LOCKED.
- `markOrderPaid`: `orders` FOR UPDATE ← `customers` FOR UPDATE.
- `expireDueOrders`: `orders` FOR UPDATE SKIP LOCKED فقط، فلا ينتظر طلبًا تُسجَّل دفعته. جملتان في معاملة واحدة منذ المرحلة 4أ.
- `createPaymentAttempt`: `orders` FOR UPDATE ثم إدراج المحاولة. `applyProviderSnapshot`: صف المحاولة FOR UPDATE وحده، ثم `markOrderPaid` بمعاملتها. لا يُحمل قفل محاولة أثناء طلب قفل طلب.

كل العمليات معاملات READ COMMITTED تفاعلية. القيود والـtriggers في القاعدة (T1..T7) سدّ أخير إن نسي الكود قفلًا، وأسماؤها الثابتة تُحوَّل إلى أخطاء عمل في `sql-errors.ts`.

**الانتهاء لا يعتمد على جدولة:** القراءة تستعمل `effectiveOrderStatus` فالطلب الفائت يُعرض منتهيًا، و`createOrder` يُنهي المستحق في نطاقه (العميل والعروض المرشّحة) دفعةً بعد دفعة قبل العدّ. الطلب الفائت غير المكتوب منتهيًا يبقى حاجزًا لكوبونه، وهذا الاتجاه الآمن. السكربت `pnpm --filter @masar/db orders:expire` يُنهي الباقي، ويُجدوَل بمؤقت systemd أو cron عند النشر **بدل pg-boss لهذه المهمة** (تحديث للقرار 10، القرار 41). جدولته شرط قبل فتح العلم.

**عملية الخادم الواحدة:** حدود المحاولات في الذاكرة (القرار 42) تفترض عملية Node واحدة كما في `deploy/compose.yml`. التوسع إلى أكثر من عملية ينقلها إلى مخزن مشترك.

## أساس الدفع (المرحلة 4أ، بلا مفاتيح)

التصميم في `PHASE4_PAYMENTS_DESIGN.md`، وما بُني وما ينتظر في `PAYMENTS.md` §9–§11. مغلق افتراضيًا: بلا `PAYMENTS_MODE` لا يُحمَّل مزوّد ولا يظهر زر.

| الطبقة                         | ما فيها                                                                                                                                              |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/domain/src/payments` | آلة حالة المحاولة و`decideVerification` و`paymentDeadline` و`paymentDisplayState`. خالص                                                              |
| `packages/db/src/payments`     | المحاولات والحوادث ومطالبة المزامنة. `applyProviderSnapshot` المستدعي الوحيد لـ`markOrderPaid`                                                       |
| `packages/payments`            | المنفذ `PaymentProvider` ومحوّلاته (Moyasar، ومزوّد الاختبار)، والتنسيق (`startPayment`، `syncAttempt`، المطابقة). الشبكة هنا وحدها، بـ`fetch` محقون |
| `apps/web/src/server/payments` | بناء المزوّد من الإعداد، الإجراء `payOrder`، التحقق عند العودة، ونقطة الإشعار                                                                        |

**طريق واحد إلى التفعيل:** الإشعار وصفحة العودة ومهمة المطابقة كلها تستدعي `syncAttempt`، وهي تقرأ الجلسة من المزوّد بالمفتاح السري ثم `applyProviderSnapshot`، وهي تستدعي `markOrderPaid`. لا تفعيل من رابط عودة ولا من جسم إشعار. استدعاء المزوّد دائمًا خارج المعاملات.

**الإشعار:** `POST /api/payments/webhooks/[provider]` يوثّق السر بزمن ثابت ويرد 2xx فورًا، والمعالجة في `after()`. إن سقطت مع إعادة تشغيل العملية فالمطابقة تحسم المحاولة.

**المطابقة:** `pnpm --filter @masar/payments payments:reconcile` تحت قفل استشاري. جدولتها مع `orders:expire` شرط قبل أي دفع.

## لوحة التحكم (المرحلة A1)

`/admin` خارج `app/[locale]` بتخطيط جذري خاص (`app/admin/layout.tsx`) وقاموس خاص (`i18n/admin`)، ومستثناة من قواعد إعادة كتابة اللغات في `next.config.ts`. المواصفة في `ADMIN_DESIGN.md`، والقراران 61 و62.

| الطبقة                                    | المسؤولية                                                                                                                                                                        |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/domain/src/staff`               | خريطة الصلاحيات، سياسة كلمة المرور، TOTP (HMAC محقون)، انتقالات القفل، عمر الجلسة ومرحلتها، قاعدة آخر مالك                                                                       |
| `packages/db/src/staff`                   | الحسابات، الجلسات، الخطوة الثانية، التدقيق، أرقام «نظرة عامة»، و`crypto/` (scrypt، AES-GCM، الرموز)، وأوامر المالك                                                               |
| `apps/web/src/server/admin`               | الحارس `requireStaff`، الكوكي، الدخول، الخطوة الثانية، كلمة المرور، إدارة الموظفين، و`actions/` (كل Server Actions)                                                              |
| `apps/web/src/components/admin`           | الهيكل (شريط جانبي، وشريط تبويب على الهاتف)، النماذج، الجداول، رمز QR                                                                                                            |
| `apps/web/src/proxy.ts` و`next.config.ts` | الوسيط يعلّم طلبات اللوحة المفتوحة بترويسة داخلية ويضع `noindex` و`no-store`. ما بلا علامة (لوحة مغلقة، أو كتابة أخرى لاسمها) تخدّمه قاعدة `beforeFiles` كمسار مجهول: 404 العامة |

**مسار الدخول:** كلمة المرور ← جلسة بلا إثبات الخطوة الثانية ← الحارس يوجّهها إلى مرحلتها (`mfa_verify` أو `password_change` أو `mfa_enrol`) ← رمز جديد عند إتمام الخطوة ← `full`. الجلسة تُقرأ من القاعدة مع كل طلب (`cache` لكل طلب)، فالإلغاء والتعطيل يسريان فورًا.
